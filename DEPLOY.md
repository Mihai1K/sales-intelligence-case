# Публикация кейса на GitHub Pages

Страница — один самодостаточный `index.html` в корне, без сборки и
зависимостей. Единственный внешний ресурс — Google Fonts.

## Как опубликовать

```bash
cd portfolio-case
git init
git add .
git commit -m "Инженерный кейс: сверка данных как контрольный гейт"
git branch -M main
git remote add origin git@github.com:Mihai1K/sales-intelligence-case.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch**,
ветка `main`, папка **`/ (root)`**.

Через минуту страница будет на
`https://mihai1k.github.io/sales-intelligence-case/`.

Файл `.nojekyll` уже добавлен — без него Jekyll игнорирует файлы,
начинающиеся с подчёркивания.

## Проверить локально

```bash
python3 -m http.server 8000
```

Открыть `http://localhost:8000`.

## Что проверить перед публикацией

- **Обе темы.** Страница читает системную тему. Переключите тему ОС и
  убедитесь, что обе читаемы. Все цвета объявлены токенами в трёх блоках
  `:root` — светлом, `prefers-color-scheme: dark` и `[data-theme="dark"]`.
- **Узкий экран.** Блоки вывода команд прокручиваются внутри себя, страница
  вбок не едет.
- **Шрифты.** Если Google Fonts недоступны, сработает системный запасной
  стек — вёрстка не разъезжается.

## Если кейс идёт вместе с кодом

Два варианта.

**Один репозиторий.** Положить `index.html` и `README.md` в корень проекта —
Pages раздаёт из корня, README виден на главной странице репозитория.
Читателю сразу доступен и разбор, и исходники.

**Два репозитория.** Кейс отдельно, код отдельно, со ссылками друг на друга.
Имеет смысл, если код содержит то, что не хочется публиковать.
